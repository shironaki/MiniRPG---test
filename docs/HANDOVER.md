## 1. Что это за проект

**MiniRPG** — браузерная RPG без единой зависимости: ни сборщика, ни
`node_modules`, ни фреймворка. Только HTML + CSS + чистый JavaScript,
подключаемый обычными `<script>`-тегами. Тесты — собственный микро-раннер на
Node `vm`, тоже без зависимостей. Это осознанное архитектурное решение: проект
открывается двойным кликом по `index.html` и разворачивается на GitHub Pages
без CI-сборки.

В репозитории **две версии игры одновременно**:

| Версия | Путь | Что это |
|--------|------|---------|
| **v1** | `/` (корень: `index.html`, `js/`, `assets/`) | Готовая кликовая RPG «Mini RPG 9.0 — The Lost Kingdom»: комнаты, пошаговый бой, квесты, крафт, карма, союзники, данжи. ~4 900 строк. **Стабильна, считается завершённой.** |
| **v2** | `/v2/` (`v2/index.html`, `v2/js/`) | Новая 2D-версия со свободным перемещением по миру на Canvas. ~3 800 строк. **Активная разработка.** |

v2 **не форкает** логику v1 — она подгружает настоящие `../js/*.js` (бой,
предметы, квесты, крафт, диалоги) и надстраивает над ними 2D-мир. Это главный
принцип: одна игровая логика, две оболочки.

**Долгосрочная цель владельца:** v2 должна стать игрой «в духе Stardew Valley»
(концептуально, не копией): маленькие персонажи, живые локации, глубокое
взаимодействие с NPC, свобода действий. Развитие — постепенное, но заметное:
каждый заход даёт видимый игровой результат.

## 2. Как запустить за 60 секунд

```bash
git clone https://github.com/shironaki/MiniRPG---test.git
cd MiniRPG---test
npm run serve          # http://localhost:8080  — сборки не требуется
# или PORT=3000 npm run serve
```

* `http://localhost:8080/` — v1 (кликовая версия).
* `http://localhost:8080/v2/` — v2 (2D, основная работа идёт здесь).

Тесты:

```bash
npm test               # ожидаемо: 119 + 24 + 39 + 5 + 5 = 192 passed
```

Раскладка прогонов: `tests/game.test.js` (119, логика+баланс v1),
`tests/integration.test.js` (24, UI-обвязка v1), `v2/tests/engine.test.js`
(39, движок и системы v2), `v2/tests/battle.test.js` (5),
`v2/tests/menus.test.js` (5).

Проверка синтаксиса (её же делает CI):

```bash
for f in js/*.js scripts/*.js tests/*.js v2/js/*/*.js v2/js/main.js; do node --check "$f"; done
```

## 3. Управление в v2 (чтобы понимать, что тестируешь руками)

| Клавиша | Действие |
|---------|----------|
| `WASD` / стрелки | ходьба (4 направления, есть инерция) |
| `E` | контекстное действие: поговорить, войти в здание, рубить/собирать, работать на грядке |
| `I` | рюкзак (инвентарь + ресурсы) |
| `Esc` | закрыть меню |
| тач | виртуальный джойстик + кнопки, есть переключатель схемы управления и фуллскрин |

Подсказка над героем всегда показывает, что именно сделает `E`.

## 4. Состояние игровых систем v2 (что уже работает)

### 4.1 Движок и мир
* Игровой цикл с фиксированным шагом (`v2/js/engine/loop.js`), камера со
  слежением и клампом к границам карты, тайловая карта 32 px с коллизиями.
* Три зоны (`v2/js/world/maps.js`): **деревня** (мирная), **лес**, **пещера**.
  Переходы — через порталы/выходы на краях карт, спавн-точки заданы явно.
* Весь мир нарисован **процедурным пиксель-артом** в рантайме
  (`render/tilesart.js`), растровых спрайтов в проекте больше нет — PNG-мобов
  удалили намеренно. Трава и вода анимированы.

### 4.2 Персонажи
* Герой — послойный пиксель-арт риг (`render/character.js`): тело, одежда,
  волосы, экипировка отдельными слоями, 4 направления, цикл ходьбы,
  перекрашиваемые части. Размер намеренно **чиби** (`H = h * 1.7`).
* Мобы (`render/mobs.js`): гоблин, скелет, волк — в том же стиле, в мире и в бою.
* В деревне мобов нет — это железное правило владельца.

### 4.3 Бой
* Столкновение с врагом в мире открывает **настоящий бой из v1**
  (`js/battle.js`) в 2D-оболочке (`v2/js/battle/battle2d.js` + `battleui.js`):
  навыки, стихии, статусы, побег, награды — всё из основной логики.

### 4.4 Деревня и интерфейсы
* Здания все **разные и соответствуют функции**: дом, лавка, кузница, врата
  испытаний (`render/buildings.js`, с анимированным дымом и порталом).
* Меню (`v2/js/ui/menus.js`): лавка, кузница, квесты, диалоги, данж, рюкзак,
  экран жителей — все работают поверх систем v1.
* Пруд, ручей, мост, деревья, заборы — локация «обжитая», не пустая.

### 4.5 Время суток
* Внутриигровые часы и календарь: минуты идут постоянно, в полночь счётчик дня
  увеличивается. HUD показывает `День N · ☀️ 08:09`.
* Динамическое освещение: цвет и плотность ночного оверлея интерполируются по
  ключевым часам (рассвет/день/закат/ночь), окна домов **светятся ночью**.

### 4.6 Живые NPC и дружба
* Трое жителей (`v2/js/entities/npc.js`): **Марта** 👩‍🌾, **Борис** 🧔,
  **Лена** 👧. У каждого свой облик, характер, реплики и **суточное расписание**
  (дом → работа → площадь → вечерняя прогулка → сон). Ходят сами, есть защита
  от застревания. Над головой — табличка с именем.
* Дружба (`v2/js/world/social.js`): очки → до 10 ❤️. Раз в игровой день можно
  **поговорить** (+20) и **подарить** (+35, любимый подарок +90, помечен 💖).
  Лимиты сбрасываются на рассвете.

### 4.7 Сбор ресурсов
* Узлы (`v2/js/world/resources.js`): 🌳 дерево → 🪵, 🪨 камень, 🫐 куст → ягоды
  (иногда 🌰 семена), 🌿 травы. Расставлены в деревне и в лесу.
* `E` — быстрый сбор без паузы: узел шатается, истощается, показывает пенёк /
  обломки / голый куст и **отрастает** через заданное время.
* Ресурсы видны в HUD и в рюкзаке, их можно дарить NPC.

### 4.8 Ферма
* Грядка 3×2 у кузницы (`v2/js/world/farming.js`). Контекстное `E` по
  состоянию клетки: **вспахать → посадить (тратит 🌰) → полить → собрать 🥕**.
* Рост завязан на календарь: на рассвете растение растёт **только если его
  полили накануне**. Морковь зреет за 2 дня, иногда даёт двойной урожай.
* Морковь любят Марта и Лена — цикл замыкается: вырасти → подари → дружба.

## 5. Как проверялась работа (и как проверять дальше)

Помимо `npm test` использовался **смоук-тест в заглушенном браузере**: Node
`vm` + поддельные `document`/`canvas` (Proxy, где любой метод контекста —
заглушка) + ручной `requestAnimationFrame`. Он грузит **все** скрипты в том же
порядке, что и `v2/index.html`, прогоняет ~120 кадров и дёргает реальные
действия игрока.

Так были проверены: загрузка без исключений, рендер кадров, сбор ресурса
(🪵+1 в HUD), разговор с жителем (+20 к дружбе), цепочка фермы через `E`
(вспахал → посадил, семена 6→5 → полил → через два рассвета «созрело»).

Скрипт смоука лежал во временной папке и в репозиторий не коммитился —
**имеет смысл восстановить его как `v2/tests/smoke.js`**, это первая
очевидная задача для нового разработчика (см. раздел 8).

Важные грабли, найденные на этом пути (не наступать снова):

* Ввод **edge-triggered**: `input.press(code)` без последующего
  `input.release(code)` второй раз не сработает. В тестах «нажатие» — это
  `press` + `release`.
* Новый файл нужно добавить **в три места**: `v2/index.html`, список `FILES`
  и список `EXPORTED` в `v2/tests/harness.js`. Иначе `X is not defined`.
* Классы и `const` верхнего уровня в `vm`-песочнице **не попадают** в объект
  sandbox — экспортировать их надо явно:
  `vm.runInContext("globalThis.__all = { MAPS, Player, ... }", sandbox)`.
* В проекте нет headless-canvas (`node-canvas`, PIL, sharp отсутствуют).
  Для визуальной проверки пиксель-арта использовался приём: Node генерирует
  PPM-файл, затем ImageMagick (`convert-im6.q16`) конвертирует его в PNG.
* `fullyGeared(null, level)` игнорирует первый аргумент **намеренно** — это не
  баг, «чинить» не надо.
* `journal.onResourceGathered` вызывается через `&&`-guard: метода может не
  быть, не считать его гарантированным.

## 6. Правила работы (кратко — полностью в `AGENTS.md`)

1. **Основу не трогаем:** готовая игра v1 в корне (`index.html`, `style.css`,
   `js/**`, `assets/**`) закончена и остаётся как есть. Вся разработка —
   внутри папки `/v2`.
2. Лицензия и копирайт `Copyright (c) 2026 shironaki` — **неприкосновенны**.
3. Ветка **`main` — стабильная основа-релиз**: напрямую не пушить, изменения
   попадают туда через PR, который вливает владелец.
4. Работать **в новой ветке** от `main`.
5. Протокол: `SCAN → AUDIT → FIX → VERIFY → EXTEND → COMMIT → LOG`.
6. Никаких зависимостей и сборщиков. Никакого `--force`.
7. Коммиты атомарные; тесты зелёные до и после; об ошибках сообщать честно.

Автоматический контроль (лёгкий, не бюрократия): `.github/workflows/guard.yml`
роняет PR при попытке изменить основу v1, лицензию или добавить зависимости;
`.github/CODEOWNERS` зовёт владельца в ревью; `.github/workflows/ci.yml` гоняет
синтаксис и тесты на каждый push. Правка `v2/js/main.js` разрешена, CI лишь
помечает такой PR предупреждением.

## 7. Где начинать читать код

Рекомендуемый порядок (полная карта — в `ARCHITECTURE.md`):

1. `v2/index.html` — порядок загрузки скриптов = порядок зависимостей.
2. `v2/js/main.js` — оркестратор: `loadZone`, `update`, `render`, `findNearest`,
   `openInteraction`, часы и день, HUD. Менять можно, но осознанно — от него
   зависит вся сцена.
3. `v2/js/world/maps.js` — данные всех зон: тайлы, здания, NPC, ресурсы, грядки.
   Большинство контентных правок делается именно здесь и это безопасно.
4. Системы по одной: `world/social.js`, `world/resources.js`, `world/farming.js`,
   `entities/npc.js` — маленькие, чистые, с тестами.
5. `v2/js/render/*` — только рисование, игровое состояние здесь не меняется.

## 8. Дорожная карта (следующие шаги, согласованы с владельцем)

Ближайшее, по убыванию приоритета:

1. **`v2/tests/smoke.js`** — вернуть смоук-тест в репозиторий и подключить к
   `npm test`. Дёшево и сразу страхует от «белого экрана».
2. **Большой город с интерьерами** — заходить внутрь дома, лавки, кузницы:
   отдельные маленькие карты-интерьеры, мебель, NPC внутри.
3. **Мини-квесты от жителей** на порогах дружбы (2 ❤️, 5 ❤️, 8 ❤️) —
   поручения на ресурсы/урожай с наградой и репликами.
4. **Собственный дом игрока**: сундук-хранилище, сон до утра (пропуск ночи),
   апгрейды.
5. **Рыбалка и готовка** — ещё одна петля «добыл → приготовил → подарил».
6. Больше культур на ферме (сезоны), инструменты и их прокачка.

Дальняя перспектива: расширение мира, погода и сезоны. Кооператив/онлайн —
**сильно потом**, сейчас не проектировать под него.

Стиль работы, который владелец просил сохранять: **крупными пачками** — за
заход несколько связанных систем, дающих заметный игровой результат, с отчётом
в конце. Не мелкими косметическими правками.
