# 🗺️ ARCHITECTURE — карта кода MiniRPG

Сопроводительный документ к [`HANDOVER.md`](HANDOVER.md). Здесь — что в каком
файле лежит, как файлы связаны и какие правила действуют при добавлении нового.

Принципы, на которых всё держится:

1. **Ноль зависимостей.** Никакого npm-рантайма, сборщика, транспайлера.
   Браузер грузит файлы `<script>`-тегами по порядку; порядок = зависимости.
2. **Один файл — одна система.** Классы/каталоги данных, без god-объектов.
3. **Логика отдельно от рисования.** Игровое состояние живёт в `world/` и
   `entities/`, пиксели — в `render/`. Рендер ничего не мутирует.
4. **Совместимый экспорт** в конце каждого файла, чтобы тот же исходник
   грузился и в браузере, и в Node-тестах:
   ```js
   if (typeof module !== "undefined" && module.exports) module.exports = { Thing };
   ```
5. **v2 переиспользует v1.** Бой, предметы, квесты, крафт — из `js/*`.

## 3. v2 — `v2/js/` (2D-версия, активная разработка)

Порядок загрузки в `v2/index.html` (он же порядок зависимостей):

```

engine/vec.js  engine/input.js  engine/camera.js  engine/loop.js
world/tiles.js world/tilemap.js world/weather.js world/social.js world/resources.js
world/farming.js world/fishing.js world/cooking.js world/tools.js
world/animals.js world/mines.js world/decor.js
```

### 3.1 `engine/` — каркас
| Файл | Что делает |
|------|-----------|
| `vec.js` | векторная мелочь |
| `input.js` | `Input`: клавиши, **edge-triggered** `wasPressed`/`consumePressed`, аналоговый джойстик, `attach(document)` |
| `camera.js` | слежение за героем, кламп к границам карты |
| `loop.js` | игровой цикл с фиксированным шагом, `update(dt)` + `render()` |

⚠️ `input.press(code)` регистрирует нажатие один раз; повторное сработает
только после `release(code)`. В тестах всегда «press + release».

### 3.2 `world/` — состояние мира (чистая логика, покрыта тестами)
| Файл | Что делает |
|------|-----------|
| `tiles.js` | типы тайлов, проходимость (трава, вода, мостовая, песок, море, пальма) |
| `tilemap.js` | сетка 32 px, коллизии, перевод координат |
| `weather.js` | `WeatherSystem`, `SEASONS`, `WEATHER_TYPES`: календарь 4 сезонов (28 дней на сезон, 112 дней в году), детерминированная погода (ясно, облачно, дождь, гроза, туман, снегопад), автополив грядок в дождь, прогноз погоды на завтра |
| `maps.js` | **данные всех зон**: `village`, `beach`, `forest`, `cave`, `home`, `shop_in`, `forge_in`, `mine_floor_*` — тайлы, `buildings`, `npcs`, `resources`, `farm`, `furniture`, `portals`. Контентные правки делаются тут |
| `social.js` | `Social`: очки дружбы → сердца, лимиты «раз в день» на разговор/подарок, любимые подарки |
| `resources.js` | `RESOURCES` (каталог: 🪵 дерево, камень, руды, слитки, самоцветы, яйца, молоко, шерсть, 🌰 семена, 🥕 овощи, 🍓 клубника, 🍅 томаты, 🌽 кукуруза, 🎃 тыква, 🌾 пшеница, 🍎 яблоки, 🍒 вишня, 🐚 ракушки, 🪵 плавник, 🌿 ламинария, 🐟 рыба, 🍲 блюда), `NODE_TYPES`, `ResourceNode` (сбор, истощение, респавн), `ResourceBag` (сумка) |
| `farming.js` | `Farm`, `FarmPlot`, `CROPS`, `CROP`. Конечный автомат грядки: `empty → tilled → growing → ready → (harvest) → tilled`. 6 видов культур, `onNewDay(day, isRaining)` с автополивом в дождь. `rng` инъектируемый |
| `animals.js` | `FarmAnimal`, `RanchSystem`, `ANIMAL_TYPES`: содержание скота (куры, коровы, овцы), ласка, кормление сеном/пшеницей, сбор яиц/молока/шерсти, качество продукции |
| `mines.js` | `MinesSystem`, `SmeltingSystem`, `SMELTING_RECIPES`: многоярусные процедурные шахты, рудные жилы (медь, железо, золото, уголь, самоцветы), лестницы спуска/подъёма, плавка слитков в печи |
| `decor.js` | `DecorSystem`, `FLOOR_STYLES`, `WALL_STYLES`, `DECOR_CATALOG`: кастомизация стен и полов, каталог декоративной мебели |
| `fishing.js` | `FishingSystem`, `FISH_TABLE`, `OCEAN_FISH_TABLE`: ловля пресноводной рыбы в пруду (окунь, карп, щука, раки) и морской рыбы на побережье (камбала, тунец, омар, жемчуг), влияние удочки, шансы сокровищ |
| `cooking.js` | `CookingSystem`, `RECIPES`: домашняя готовка и кулинарные деликатесы (омлет, блинчики, сыр, стейк, золотой сидр, похлёбка, уха, пирог, варенье, паста) |
| `tools.js` | `Tools`, `TOOL_TIERS`: уровни и прокачка удочки, топора, кирки и лейки в кузнице |
| `requests.js` | `Requests`, `REQUEST_POOL`: поручения жителей на ресурсы, продукты, руды, рыбу и блюда за золото и дружбу |

### 3.3 `entities/` — то, что двигается

| Файл | Что делает |
|------|-----------|
| `battle2d.js` | оборачивает `Battle` из `js/battle.js` |
| `battleui.js` | экран боя поверх канваса |

### 3.5 `ui/menus.js`
`V2Menus`: лавка, кузница, квесты, диалог, данж, рюкзак (предметы + ресурсы),
экран жителей (сердца, подарки). Всё — поверх систем v1.

### 3.6 `render/` — только пиксели
| Файл | Что рисует |
|------|-----------|
| `tilesart.js` | `TileArt`: трава, вода, деревья, тропинки, камни, заборы; анимации травы/воды |
| `buildings.js` | `BuildingArt`: дом, лавка, кузница, врата испытаний; дым, портал, **светящиеся ночью окна** |
| `character.js` | `CharacterRig`: послойный пиксель-арт героя и NPC (тело/одежда/волосы/экипировка), 4 направления, цикл ходьбы, перекраска |
| `mobs.js` | `MobRig`: гоблин, скелет, волк |
| `renderer.js` | дирижёр отрисовки: `drawMap`, `drawBuildings`, `drawFarm`, `drawResourceNodes`, `drawNPCs`, `drawEnemies`, `drawPlayer`, `drawPortals`, `drawInteractables`, `drawNightOverlay` |

Растровых спрайтов в v2 **нет** — весь арт процедурный, генерируется кодом.

### 3.7 `v2/js/main.js` — оркестратор (**ЗАМОРОЖЕН**)
Собирает всё вместе: `loadZone(id, spawn)`, игровой цикл `update`/`render`,
внутриигровые часы и счётчик дня, `findNearest()` (что сейчас под `E`:
`spot` / `npc` / `resource` / `farm`), `openInteraction`, `gatherFrom`,
`workPlot`, HUD и всплывающие подсказки, мобильные контролы, `window.__v2`
для отладки.

Читать — обязательно. Менять — только с письменного разрешения владельца
(см. `AGENTS.md`, правило 4).

Харнессы (`tests/harness.js`, `v2/tests/harness.js`, `v2/tests/menus-harness.js`,
`v2/tests/battle-harness.js`) грузят **настоящие исходники** в Node `vm` с
минимальными браузерными заглушками. Собственный микро-раннер: `describe`,
`it`, `expect(...).toBe(...)` — без библиотек.

### Добавляешь новый файл — три обязательных места
1. `<script src="...">` в `index.html` или `v2/index.html` (в правильном месте порядка).
2. Список `FILES` в соответствующем харнессе.
3. Список `EXPORTED` (имена классов/констант), иначе тест получит `X is not defined`.

Заглушки в харнессе должны поддерживать то, что реально вызывает код: у `style`
нужны `setProperty`/`removeProperty`/`getPropertyValue`, у `classList` —
`add`/`remove`/`toggle`/`contains`.

## 6. Соглашения по коду

* Vanilla JS, классы, без модулей ES (`import/export` не использовать —
  файлы грузятся тегами).
* Комментарии — по-английски, тексты в интерфейсе игры — по-русски.
* Рандом в игровых системах — через инъектируемый `rng`, чтобы тесты были
  детерминированными (`new Farm({ rng: () => 0.9 })`).
* Никакого `innerHTML` с пользовательским вводом без экранирования: в проекте
  был отдельный security-проход (`dea7456`), не откатывать.
* Игровые данные (числа, координаты, тексты) — в `maps.js`/`data.js`,
  не разбрасывать по коду.
